# Vana

## Decentralized AI and Blockchain Infrastructure for User-Owned Data

> **Vana** is an open and decentralized data network built to empower individuals to own, control, and monetize their personal data in the AI economy. Powered by an **EVM-compatible Layer 1 blockchain**, Vana creates an open infrastructure where users can securely contribute data, participate in decentralized data collectives, and capture value from the AI models and applications built using their data. 

---

## Current Features

- **EVM-Compatible Layer 1 Blockchain**: A dedicated blockchain infrastructure designed to support decentralized data ownership, smart contracts, tokenized data assets, and AI-powered applications.
- **Decentralized AI Infrastructure**: An open infrastructure that enables AI developers, researchers, and builders to access community-owned datasets and develop AI models, applications, and intelligent agents.
- **Data Liquidity Pools (DLPs)**: Decentralized data pools that allow individuals to contribute, validate, and collectively monetize their data while participating in the AI data economy.
- **Smart Contract Support**: On-chain application logic for managing DataDAOs, data liquidity pools, staking, governance, tokenization, and reward distribution.
- **Tokenized Data Economy**: A blockchain-based economic model that connects data contributors, AI developers, and decentralized communities through digital assets and incentive mechanisms.
- **Multi-Participant Network Governance**: A decentralized ecosystem where data contributors, validators, developers, and DataDAO communities participate in network operations and governance.
- **AI Model Development and Training**: Enable AI researchers and developers to leverage collectively contributed datasets to build more diverse, personalized, and human-grounded AI models.
- **VANA Token Integration**: Native network token functionality supporting transaction fees, staking, network security, governance, and participation in the decentralized data economy.

## Quick Start

```bash
git clone <git-repository-url>
cd <project directory name>

# Install and start backend dependencies
npm install
npm start

# Install frontend dependencies 
cd frontend
npm install

# Run both with one command from the root:
npm start
```

## Config

- **JWT issuance** – `POST /api/auth` in `controllers/auth.js` signs a JWT with `config.JWT_SECRET_KEY` (see `SESSION_EXPIRES_IN`). The payload only contains `user.id` so you can safely extend it.
- **Client storage** – Tokens are pushed into Axios’ default headers via `client/src/helpers/setAuthToken.js`. Persist them in `localStorage`/`sessionStorage` from your auth screen and call `setAuthToken(token)` on boot.
- **Protected routes** – `middleware/auth.js` expects the token in the `x-auth-token` header and injects `req.user`. Use the middleware on any route that needs authenticated identity.

## Contributing Guidelines

### Pre-PR Checklist

- [ ] Branch is updated with `main`  
- [ ] No linting errors
- [ ] No stray console logs or unused variables  
- [ ] UI changes tested on desktop and mobile  
- [ ] Added documentation or comments where needed  
- [ ] Any new `.env` variables are documented  

### Pull Request Rules
- Use clear PR titles:
  - `feat: add tournament lobby UI`
- PR description must include:
  - What changed  
  - Why it changed  
  - How to test  
  - Screenshots for UI updates  
- Tag related issues/tasks.
